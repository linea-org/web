Replay is not a retry button on the whole graph. It is a request to run one step again against the payload that step originally received.

That payload is not in your prompt file. It is the output of the steps before it, plus whatever memory and tool results were in scope. If Linea did not execute the run, that record does not exist.

![Checkpointed run surface](/ref/rightfit-jobs.jpg)

## What the checkpoint holds

A checkpoint is the exact input a node saw, written when Linea ran it. Replay loads that record and calls the node again. Nothing upstream has to move.

```json
{
  "runId": "run_4f2a",
  "step": "draft_reply",
  "input": {
    "thread": "cust_8891",
    "facts": ["plan is annual", "last invoice failed"],
    "draft": null
  }
}
```

Without that object, "replay step four" is a polite way to say "run the graph again and hope."

## Full re-run vs step replay

| Approach | What you pay for | What you get back |
| --- | --- | --- |
| Full re-run | Every step before the break | A new run, not the same input |
| Step replay | The one step you named | The same checkpoint, a new output |

The difference is the host. A framework can model the graph. It cannot give you the input it never stored.
